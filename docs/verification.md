# 驗證結果與限制

[← 回 README](../README.md)

## 驗證範圍

程式是在**沒有音效裝置**的雲端 Linux 環境開發的，之後在 Windows 實機上使用。

**實機使用**

- 桌上型喇叭 + 桌上型麥克風，Discord 通話：回聲消除有效，對方聽不到回音。
- Discord 的噪音抑制開 Krisp 時，回聲消除照常有效，還能去除機械鍵盤聲。
- Hey Siri 防誤觸：30 dB 的淺陷波（舊版 `apple`）擋不住；`apple-deep` 有效；新預設 `deep-wide` 還沒在實機上測過。
- 4K 螢幕：視窗大小、文字與圖示顯示正常（v0.2.0 起）。

**離線驗證**

- 所有聲音處理都用合成訊號和 TTS 語音做過離線測試。
- 跑過模擬多個裝置、各自時脈不同的多執行緒整合測試。
- Windows 版 exe 在 GitHub 的 Windows 機器上打包，並跑過自我檢測：
  - 引擎能載入、離線回聲消除量正常
  - Siri 陷波有作用
  - 圖示有包進 exe
- 完整測試也在 Windows 上跑過，全部通過。

## 回聲消除

**測試方式**

- 麥克風訊號 = 近端語音 + 房間脈衝響應 × 延遲後的參考 + 雜訊。
- 房間脈衝響應包含直達聲和 200 ms RT60 的尾音。
- 依序跑三段：只有遠端講話 40%、只有近端講話 20%、雙方同時講話 40%。

**表格說明**

- ERLE：回聲衰減量，越大越好。
- STOI：清晰度，1 = 完全不變。

|---|---|---|---|---|---|
| webrtc | 關 | 40 ms | **41.9 dB** | 1.00 | 0.59 (0.74) |
| webrtc | 開 | 40 ms | **53.9 dB** | 0.99 | 0.55 (0.74) |
| webrtc | 關 | 150 ms | 42.2 dB | 0.99 | 0.60 (0.74) |
| speex | 關 | 40 ms | 23.5 dB | 0.99 | **0.98** (0.74) |
| speex | 開 | 40 ms | 43.3 dB | 0.97 | **0.94** (0.74) |
| speex | 開 | 150 ms | 38.1 dB | 0.95 | 0.94 (0.74) |
| nlms | — | 40 ms | 18.0 dB | 1.00 | 0.92 (0.74) |

### 其他項目

- **時脈漂移**
  - 生產端 ±500 ppm 時，估計值為 499.5 / −499.8 ppm。
  - 水位維持在 10–20 ms，沒有欠載。
- **整合測試**
  - 完整多執行緒程式接上模擬裝置：loopback +100 ppm、CABLE −60 ppm。
  - ERLE 約 40–41.6 dB，沒有欠載。
- **延遲估計（GCC-PHAT）**
  - 誤差 < 1 ms。
  - 參考訊號晚到（負延遲）也能正確判讀。
- **延遲補償**
  - 延遲 600 ms 時，NLMS 的 ERLE 是 −2.8 dB。
  - 加上 `--delay-ms 590` 後變成 17.5 dB。
- **測試中發現的 AEC3 行為**
  - 輸入接近滿刻度，或出現極不自然的大聲嘶聲時，AEC3 會停止消除，很久不會恢復。
  - TTS 語音沒有遇到這個狀況。
  - 這是程式會提醒「麥克風太大聲」的原因（見[安裝說明](setup.md#windows-麥克風音量)）。

| `deep-wide`（合成語音）：目標頻帶衰減 / 總能量 / 頻帶外 LSD / STOI | ≥ 45 dB / −0.23 dB / 0.00 dB / 0.97 |

## 已知限制

- 回聲消除只能消掉線性的部分：喇叭失真、機殼共振消不掉，喇叭越大聲殘留越多。
- WebRTC 引擎的參數沒辦法調，例如雙講時的積極程度。
- Speex / NLMS 只在 16 kHz 處理，你的聲音頻寬會變成約 7 kHz。
- 「系統主音量」大幅改變時，回聲消除可能要幾秒重新收斂。
- 程式沒在跑時，`CABLE Output` 沒有聲音。
- Hey Siri 防護的限制見[這裡](siri-guard.md#限制)。
