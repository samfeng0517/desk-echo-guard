## 對方還是聽到回音

**最常見原因：** 通話軟體沒有選到「回聲消除麥克風」，或程式沒在運作。

1. 剛開始通話的 **1–3 秒**有一點回音是正常的，等一下再聽。
2. 打開程式的 **首頁**，確認是「**回聲消除：運作中**」。不是的話按 **開始**。
3. Discord：**使用者設定 → 語音與視訊 → 輸入裝置**，確認是 **回聲消除麥克風**（或 **CABLE Output**）。
   - LINE：**設定 → 通話 → 麥克風**。
4. Discord 的 **回音消除** 要**關掉**。
5. 有開 **NVIDIA Broadcast** 的話，關掉它。
6. 請對方說話，看首頁：
   - **喇叭播放中** 不會跳 → 程式聽錯喇叭了。到 **裝置** 頁，把 **喇叭** 改成你真正發出聲音的那一組。
   - **送給對方** 也一直跟著跳 → 繼續下一步。
7. **把喇叭音量調小一點**，或把喇叭轉個方向、離麥克風遠一點。
   - 喇叭開太大聲時聲音會「破掉」（失真），破掉的部分程式扣不掉。
8. 有沒有出現「麥克風太大聲」的黃色警告？有的話照[這一節](#出現麥克風太大聲的警告)處理。
9. 量一次延遲：
   1. 到 **進階** 頁。
   2. 按 **量測延遲**，喇叭會播大約 4 秒的「沙沙」聲，這段時間保持安靜。
   3. 如果結果建議要調整，按 **套用建議值**。
10. 剛大幅調整過 Windows 的音量的話，等幾秒，程式需要重新適應。

## 對方說我的聲音斷斷續續、被吃字

**最常見原因：** 你們**同時講話**時，預設的消除方式會把你的聲音也壓低。

1. 問對方：是「兩個人同時講話時」才被吃掉，還是「一直都」斷斷續續？
2. **同時講話時才被吃掉：**
   1. 到 **進階** 頁。
   2. **回聲消除引擎** 改選 **Speex**。
   3. 不用重開，會自動套用。
   - 代價：你的聲音會稍微悶一點（高音少一點），剛開始要 5–10 秒才會把回音消乾淨。
3. **一直都斷斷續續：**
   1. Discord 的 **進階語音活動** 關掉。
   2. Discord 的 **輸入靈敏度** 改成手動，把門檻拉低一點；或改用「按鍵發話」。
   3. Discord 的 **自動增益控制** 關掉。
   4. 確認 Discord 的 **回音消除** 是關的，NVIDIA Broadcast 是關的。
   5. 有出現「麥克風太大聲」的警告就照[這一節](#出現麥克風太大聲的警告)處理。
4. 還是不行，可以試試把喇叭和 VB-Cable 的取樣率都設成 **48000 Hz**（選用）：
   1. 按 Windows 鍵，輸入「**控制台**」並打開。
   2. **硬體和音效 → 聲音**。
   3. **播放** 分頁：對你的喇叭按右鍵 → **內容** → **進階** → 選 **48000 Hz** 開頭的那一項 → **確定**。
   4. 對 **CABLE Input**（改名後叫「EchoGuard 內部輸出（勿選）」）做一樣的事。
   5. **錄製** 分頁：對 **CABLE Output**（改名後叫「回聲消除麥克風」）做一樣的事。
5. 都不行就看[都試過了還是不行](#都試過了還是不行)，把記錄傳給作者。

## 對方完全聽不到我

**最常見原因：** 程式沒在跑。程式沒在跑時，「回聲消除麥克風」完全沒有聲音。

1. 打開程式的 **首頁**，確認是「**運作中**」。不是的話按 **開始**。
2. 對著麥克風說話，看 **你的麥克風** 有沒有跳：
   - **沒跳** → 程式聽錯麥克風了。到 **裝置** 頁，把 **麥克風** 改成你實際說話的那一支。
   - **有跳，但「送給對方」不跳** → 到 **進階** 頁，確認 **回聲消除引擎** 不是奇怪的設定；先改回 **WebRTC** 試試。
3. 首頁兩條都會跳 → 問題在通話軟體：
   - Discord：**輸入裝置** 要選 **回聲消除麥克風**（或 **CABLE Output**）。
   - 不要選名字有「**勿選**」的裝置，那是程式自己用的。
   - Discord 的 **輸入靈敏度** 門檻是不是拉得太高？
4. 剛改過 VB-Cable 的名字？**關掉 Discord / LINE 再重開**，新名字才會出現，然後重新選一次。
5. 檢查 Windows 有沒有允許程式使用麥克風：**設定 → 隱私權與安全性 → 麥克風**，確認「**讓桌面應用程式存取您的麥克風**」是開的。

## 我聽不到對方

**最常見原因：** 通話軟體的輸出裝置選到了 VB-Cable。

1. **沒開** Hey Siri 防誤觸的人：
   - Discord 的 **輸出裝置**、LINE 的 **喇叭**，要選你**真正的喇叭**。
   - 不要選 CABLE 開頭、「勿選」或「Siri防護喇叭」。
2. **有開** Hey Siri 防誤觸的人：
   - 通話軟體的輸出要選 **Siri防護喇叭**，對方的聲音會先經過本程式，再從喇叭播出來。
   - 所以**程式一定要在運作中**，不然會完全沒聲音。
   - 到 **裝置** 頁，確認 **喇叭** 是你真正的喇叭。
3. 檢查 Windows 右下角的音量有沒有被靜音、或輸出到別的裝置（例如螢幕的喇叭、藍牙耳機）。

## 開機後沒有自動開始

**最常見原因：** 沒有開「自動啟動」，或 exe 被搬過位置。

1. 手動打開程式，到 **進階** 頁，確認 **登入 Windows 時自動啟動** 是**開的**。
2. 如果你把 `DeskEchoGuard.exe` 搬到別的資料夾、或換了新版：
   - 從新的位置**手動開一次**程式，自動啟動就會改指向新位置。
3. 看一下右下角系統匣（可能要按 **^** 展開）有沒有程式的圖示：
   - **有** → 程式有開，只是在背景。雙擊圖示看首頁的狀態。
   - 開機後 VB-Cable 有時會晚幾秒才出現，程式會自己等一下再試。等 1 分鐘還是失敗，首頁會顯示提示，按 **重新開始** 即可。
4. 防毒軟體或 Windows 的「啟動應用程式」可能把它關掉了：
   - **設定 → 應用程式 → 啟動**，確認 **DeskEchoGuard** 是開的。

## 出現「找不到 VB-Cable」

**最常見原因：** 還沒裝 VB-Cable，或裝完沒有重新開機。

1. 有裝過嗎？沒有的話照 [5 分鐘上手的步驟 1](getting-started.md#步驟-1安裝-vb-cable) 安裝。
2. 裝完有**重新開機**嗎？沒有就重開一次。
3. 還是找不到，檢查是不是被停用了：
   1. 按 Windows 鍵，輸入「**控制台**」並打開。
   2. **硬體和音效 → 聲音**。
   3. 在 **播放** 和 **錄製** 分頁的空白處按右鍵，勾 **顯示已停用的裝置**。
   4. 看到灰色的 CABLE 裝置，按右鍵 → **啟用**。
   - 或在程式的 **裝置** 頁，展開下方的區塊，按 **還原 VB-Cable 原本的設定**（會改回原本的名字並全部重新啟用）。
4. 自己在控制台把 VB-Cable 改成別的名字？到 **裝置** 頁展開 **手動指定虛擬音效線（通常不用）**，自己選對應的裝置。

## 出現「麥克風太大聲」的警告

**原因：** 麥克風的音量太大，聲音「爆掉」時，程式會暫時沒辦法消回音，而且要好一陣子才恢復。

1. 在警告上按 **開啟音效設定**。
   - 或自己開：**設定 → 系統 → 音效**，在「輸入」底下點你的麥克風。
2. 把 **輸入音量** 調到大約 **70–80%**。
3. 大聲說話試試，警告不再出現就好。還會出現就再調低一點。
4. 麥克風本身有音量旋鈕（或錄音介面有增益旋鈕）的，也一起轉小一點。

- 目標：大聲說話時，峰值不超過約 **−6 dBFS**（滿刻度的一半）。
- 為什麼：測試發現輸入接近滿刻度時，WebRTC 回聲消除會完全停止消除，而且很久不會恢復。

## VB-Cable 改名後叫什麼

VB-Cable 原本的名稱很容易搞混：叫「CABLE Input」的其實是**喇叭**，叫「CABLE Output」的才是**麥克風**。在程式的 **裝置** 頁按 **整理 VB-Cable…**，可以做兩件事（可以只做其中一件）：

**1. 改成好懂的名稱**

| VB-Cable 原本的名稱 | 改名後 | 用途 |
|---|---|---|
| `CABLE Output`（錄音裝置） | **回聲消除麥克風** | Discord / LINE 的**麥克風**選這個 |
| `CABLE-A Input`（播放裝置） | **Siri防護喇叭** | 開 Hey Siri 防誤觸時，Discord / LINE 的**喇叭（輸出）**選這個 |
| `CABLE Input`（播放裝置） | EchoGuard 內部輸出（勿選） | 程式自己用，通話軟體不要選 |
| `CABLE-A Output`（錄音裝置） | EchoGuard 內部輸入（勿選） | 程式自己用，通話軟體不要選 |

- 括號裡的驅動名稱（例如「(VB-Audio Virtual Cable)」）改不掉，會留著。
- 這等於在「控制台 → 聲音 → 裝置內容」手動改名，只改顯示的名稱，不影響驅動。改名前後程式都找得到裝置，不用改任何設定。
- 改完要**關掉 Discord / LINE 再重開**，才會看到新名稱，然後再選一次。

**2. 停用用不到的 VB-Cable 裝置**

- 例如 `CABLE In 16ch`、`CABLE-B Input`、`CABLE-B Output`。停用後 Discord / LINE 的清單會比較乾淨。
- 和在「控制台 → 聲音」對裝置按右鍵 →「停用」一樣。
- 本程式會用到的四個裝置不會被停用。
- 其他軟體（例如 OBS）有用到 CABLE-B 的話，這一項不要勾。

**想全部改回來**：**裝置** 頁下方的 **還原 VB-Cable 原本的設定**，會改回原本的名稱，並重新啟用被停用的 VB-Cable 裝置。

這幾個動作都會跳出 Windows 的「要允許此 App 變更您的裝置嗎？」，按 **是**。

## Hey Siri 還是會被叫醒

**最常見原因：** 通話軟體的輸出沒有選「Siri防護喇叭」，對方的聲音沒經過本程式。

1. 確認 **Hey Siri 防誤觸** 頁的 **啟用** 是開的。
2. 確認 Discord 的 **輸出裝置**（LINE 的 **喇叭**）是 **Siri防護喇叭**。
3. 確認首頁是「運作中」。
4. 以上都對還是會被叫醒：到 **Hey Siri 防誤觸** 頁，把 **強度** 改成 **formant**。
   - 對方的聲音會變得比較悶，但還聽得懂。
5. 老實說：這個功能**沒辦法保證 100% 擋住**。Apple 自己在發表會上用類似的方法，也有觀眾的裝置被叫醒。最保險的做法是把 HomePod / iPhone 的「嘿 Siri」關掉，或通話時把它移遠一點。

細節見 [Hey Siri 防誤觸](siri-guard.md)。

## 視窗縮小再打開後畫面破掉、提示框消不掉

v0.4.1（含）以前的版本在 Windows 10 上，把視窗縮小（或縮到系統匣）再打開後，畫面可能只畫出一部分：其他地方變成後面視窗的殘影，或一直卡著一個提示框（例如「停止」按鈕下面還掛著「開始消除回音…」）。這只是畫面沒有重畫，回聲消除本身照常運作。

- **解法：** 下載最新版的 `DeskEchoGuard.exe` 換掉舊的。
- **還沒更新前的暫時解法：** 用滑鼠拉一下視窗邊框改變大小，整個畫面就會重畫。

## 怎麼完全移除

1. **把通話軟體改回來：**
   - Discord：**輸入裝置** 改回你的麥克風，**輸出裝置** 改回你的喇叭；想要的話把 **回音消除** 打開。
   - LINE：**設定 → 通話**，麥克風、喇叭改回原本的。
2. **還原 VB-Cable 的名字**（如果有改過）：到程式的 **裝置** 頁，展開下方區塊，按 **還原 VB-Cable 原本的設定**，Windows 問的時候按 **是**。
3. **關掉自動啟動：** **進階** 頁，關掉 **登入 Windows 時自動啟動**。
4. **結束程式：** 右下角系統匣圖示按右鍵 → **結束**。
5. **刪掉程式：** 刪除 `DeskEchoGuard.exe`（以及同一個資料夾裡跟它一起下載的檔案）。
6. **刪掉設定檔（選用）：**
   1. 按 **Windows 鍵 + R**。
   2. 輸入 `%APPDATA%` → **確定**。
   3. 刪除 **desk-echo-guard** 資料夾。
7. **移除 VB-Cable（選用，其他軟體沒在用的話）：**
   1. 找到當初解壓縮的資料夾（不見了就重新到 <https://vb-audio.com/Cable/> 下載）。
   2. 對 **`VBCABLE_Setup_x64.exe`** 按右鍵 → **以系統管理員身分執行**。
   3. 按 **Remove Driver**。
   4. 重新開機。
   - 有裝 VB-CABLE A+B 的話，用它資料夾裡的安裝程式，同樣按 **Remove Driver**。

## 都試過了還是不行

把記錄傳給作者，他比較好幫你看：

1. 到 **進階** 頁，展開 **診斷**。
2. 按 **複製記錄**。
3. 貼到 LINE / Discord 傳給作者，順便說：
   - 你遇到哪個狀況（用上面的標題就好）。
   - 你用 Discord 還是 LINE。
   - 喇叭、麥克風大概是什麼（例如「筆電內建麥克風 + 小米藍牙喇叭」）。

想看更技術的說明：[進階使用：調校](usage.md#調校)、[已知限制](verification.md#已知限制)。
