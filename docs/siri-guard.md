# Hey Siri 防誤觸

[← 回 README](../README.md) ・ [5 分鐘上手](getting-started.md) ・ [常見問題](faq.md)

## 我需要這個嗎？

只有**同時符合**下面兩點才需要：

- 你家裡有 **HomePod**，或 **iPhone / iPad** 開著「嘿 Siri」。
- 通話時，對方說「Hey Siri」，從你的喇叭播出來，**真的把你的 Siri 叫醒過**。

沒遇過這個問題 → **不用開**，跳過這一頁就好。

## 它怎麼做到的（一句話版）

- 對方的聲音先經過本程式，再從喇叭播出來。
- 程式把對方聲音裡 Siri 用來辨認的**中高音削掉**。人還是聽得懂，但 Siri 比較認不出來。
- 這是仿照 Apple 在 WWDC 2026 發表會被觀察到的做法（Apple 沒有正式公開）。

## 需要多裝什麼

除了原本的 VB-Cable，還要多裝**第二條虛擬音效線 VB-CABLE A+B**：

1. 打開 <https://vb-audio.com/Cable/>。
2. 在同一頁找到 **VB-CABLE A+B** 並下載。
   - 它是「捐款軟體」：可以先免費下載使用，覺得好用再捐款給作者。
3. 解壓縮 zip。
4. 對資料夾裡的 **`VBCABLE_Setup_x64.exe`** 按右鍵 → **以系統管理員身分執行** → **是**。
5. 按 **Install Driver**。
6. **重新開機。**

裝好之後再做一次改名，讓名字好懂：

1. 打開程式，點左邊的 **裝置**。
2. 按 **整理 VB-Cable…**，勾 **改成好懂的名稱**，按確認，Windows 問的時候按 **是**。
3. 改好後會多一個叫「**Siri防護喇叭**」的喇叭。

## 怎麼開

1. 點左邊的 **Hey Siri 防誤觸**。
2. 打開 **啟用**。
3. 到 Discord：**使用者設定 → 語音與視訊 → 輸出裝置** 選 **Siri防護喇叭**。
   - 沒改名的話選 **CABLE-A Input**。
   - LINE：**設定 → 通話 → 喇叭** 選 **Siri防護喇叭**。
4. 程式的 **裝置** 頁裡的 **喇叭** 保持選你**真正的喇叭**，不要動。
5. 關掉 Discord / LINE 再重開一次（剛改名的話才看得到新名字）。

這是唯一多出來的通話軟體設定：**輸出（喇叭）改選「Siri防護喇叭」**。麥克風一樣選「回聲消除麥克風」。

![Hey Siri 防誤觸頁](images/siri-light.png)

> **注意：** 開了之後，對方的聲音一定要經過本程式才播得出來。**程式沒在跑，你就聽不到對方。** 不想用了，記得把通話軟體的輸出改回你的喇叭。

## 要選哪個模式、哪個強度？

**模式（什麼時候處理對方的聲音）**

| 模式 | 什麼時候處理 | 優點 | 缺點 |
|---|---|---|---|
| **always**（一直處理，預設） | 一律處理 | 最保險；延遲只多 0.0125 秒 | 對方的聲音整通電話都比較悶 |
| **heysiri**（只在「Hey Siri」時處理，v0.4.6 新增） | 聽到「Hey」後面接「s」音才開始處理 | 平常的聲音完全不動，中文的「四、謝謝、是」幾乎不會被處理到 | 辨識模型是用合成語音訓練的，偶爾會漏掉（測試約 9 成辨識到）；只處理到後半句，擋住的機會比 always 低；延遲多約 0.07 秒 |

- **heysiri 怎麼運作：**
  1. 聽到「s」音的當下，檢查前面 0.4 秒像不像「Hey／嘿」。像，才開始處理。
  2. 0.12 秒和 0.25 秒後再各檢查一次：聽起來還像「Hey Si…」「Hey Sir…」就繼續處理到約半秒；不像（例如「Hey Sam」「黑色」）就馬上停止。
  3. 因為「Hey」在「s」音之前就講完了，不用多等，所以延遲很短。
- 用真人朗讀的中文測試：舊的「只在 s 音時處理」模式有 2 成左右的時間在處理，heysiri 只有 1.4%。
- heysiri 只認「**Hey** Siri／**嘿** Siri」。在台灣 Siri 需要說「嘿 Siri」才會醒；如果你的裝置設成英文、而且開了只說「Siri」就能喚醒，請用 always。
- 訓練用的「Hey Siri」都是英文語音念的；用中文腔調說的「嘿 Siri」沒有另外測過，可能比較容易漏。
- v0.4.6 移除了舊的 **sibilant**（只在「s」音時處理）模式：中文裡類似的音太多，常常誤削。舊設定會自動改用 heysiri。

**強度**

| 強度 | 做什麼 | 什麼時候用 |
|---|---|---|
| **deep-wide**（標準，預設） | 削掉 1–6.5 kHz。聽起來明顯變悶，像隔著一道門，但聽得懂。heysiri 模式時從「Siri」的「s」音開始削 | 先用這個 |
| **early**（加強） | 削的頻段和標準一樣，但 heysiri 模式時**對方一說「Hey」就先開始削**，等到後面沒有接「s」音再放開 | heysiri 模式還是被叫醒時 |

- **為什麼「加強」是提早削，而不是削更多？** 用開源偵測器實驗的結果：偵測器聽到前半句就可能觸發，後半句就算**整個靜音**，30 段裡還是有 25 段觸發；在「Siri」中間插入短暫的靜音、雜訊也一樣沒用。反過來，同樣的削法只要提早開始，就從「大多還會觸發」變成「完全不觸發」（[數據](siri-guard-research.md#從哪裡開始處理比怎麼處理重要)）。
- 「加強」多了一個每 0.01 秒檢查一次的小模型，專門聽「Hey」的開頭，平均在「s」音前 0.1 秒就開始削。**延遲和標準一樣（約 0.07 秒）。**
- 代價：「嘿、黑」這類開頭的音也會觸發，聲音會變悶約 0.4 秒（不會聽不見）。真人中文朗讀大約每分鐘 3 次，合計約 3% 的時間被處理（標準是 1.4%）。
- 「加強」在 **always** 模式沒有差別（本來就一直在削）。
- **v0.4.6 把「標準」加強了**：舊的「標準」只削 2.8–6.5 kHz，實機用「一直處理 + 標準」還是會被叫醒。新的「標準」連 1–3 kHz 一起削。
- **「輕微」「較淺」和舊的「加強」（把聲音削到幾乎只剩低音）已移除。** 設定檔裡的舊名稱會自動改用新的對應設定。
- **覺得「一直處理」太悶？** 把模式改成 **heysiri**：只有「Hey Siri」那半秒會變悶，其他時間完全不變。
- 新的模式和強度**還沒在 HomePod / iPhone 上實測過**，請用下面的測試工具試試看。

## 怎麼測試有沒有用

**用內建的測試工具（建議）**：它會產生一組編號的音檔，同一句「Hey Siri」有的沒處理、有的用各種設定處理過，順序打亂，播給 HomePod / iPhone 聽就知道哪種設定擋得住。

1. 在放 `DeskEchoGuard.exe` 的資料夾，按住 Shift 再按滑鼠右鍵 →「在這裡開啟 PowerShell 視窗」（或「在終端機中開啟」），輸入：

   ```
   .\DeskEchoGuard.exe --siri-test Siri測試
   ```

2. 打開新出現的 `Siri測試` 資料夾，先看 **說明與記錄表.txt**。
3. 用任何播放器從**真正的喇叭**（不是「Siri防護喇叭」）照編號播 `01.wav`、`02.wav`…（共 32 個，約 8 分鐘；每個後面有 12 秒空白），記下哪幾個編號叫醒了 Siri。
4. 全部播完再打開 **答案.txt**，數一數每種設定被叫醒幾次。

- 比較的設定：原音（對照組）、一直處理 + 標準、只在 Hey Siri 時處理 + 標準、只在 Hey Siri 時處理 + 加強。
- **iPhone 會比對是不是主人的聲音**，內建的合成聲音很可能叫不醒它。用 HomePod 測，或自己錄一句「Hey Siri」存成 wav 再加進去（可以加好幾個）：

  ```
  .\DeskEchoGuard.exe --siri-test Siri測試 --siri-test-clip 我的錄音.wav
  ```

- 「原音」那幾題如果都叫不醒 Siri，這次測試就不能用。
- 想測得更準：加上 `--siri-test-repeats 4`，每種組合播 4 次。
- 測完歡迎把結果（每種設定幾次裡被叫醒幾次）回報到 issue，這是目前最缺的數據。

**或者直接在通話裡試：**

1. 開好防誤觸，按 **開始**。
2. 用另一台手機或電腦，透過 Discord / LINE 打給自己，或請朋友幫忙。
3. 請對方說幾次「Hey Siri」（或播一段有人說「Hey Siri」的影片）。
4. 看你的 HomePod / iPhone 有沒有被叫醒。

## 對方說話時，降低其他聲音的音量

看影片、聽音樂時聽不清楚朋友說話，可以打開這個功能（v0.4.6 新增，**預設關閉**）：

1. 先照上面的步驟開啟 Hey Siri 防誤觸（對方的聲音要經過本程式，程式才知道對方在說話）。
2. 在 **Hey Siri 防誤觸** 頁的最下面，打開 **降低其他聲音的音量**。
3. 用 **降低多少** 調整幅度：60% 表示降到原本的四成，100% 是完全靜音。

- 對方一開口，其他程式（瀏覽器、音樂、遊戲…）的音量會在約 0.1 秒內降下來；對方停止說話約 1 秒後恢復。
- 做法是調整 Windows「音量混音器」裡其他程式的音量，對方的聲音不會被動到。
- 程式停止或關閉時會恢復原本的音量。萬一程式被強制結束而音量沒恢復，下次（這個功能開著時）按「開始」會自動恢復；也可以自己到 Windows 的音量混音器調回來。
- 這個功能是照 Windows 的文件寫的，**還沒在實機上測過**，有問題請回報。
- 不想繞這一圈的話，Discord 自己也有類似的功能：**使用者設定 → 語音與視訊 → 衰減**。

## 老實說的限制

- **沒辦法保證 100% 擋住。** Apple 自己在發表會用類似方法，還是有觀眾的裝置被叫醒。
- 作者實測：舊版只削高音的設定（30 dB 的窄頻、以及 v0.4.5 以前的「標準」2.8–6.5 kHz）都擋不住。v0.4.6 的新「標準」還沒在 HomePod / iPhone 上實測過。
- 用開源的語音偵測器測試時，要削到 3 kHz 以下才有效，這也是新「標準」的依據。Siri 的偵測器是否一樣，沒有人知道。
- **heysiri** 模式的辨識模型只用合成語音訓練過（找不到公開的真人「Hey Siri」錄音），真人的聲音可能辨識得比較差。漏掉的那一次就不會被處理。
- **heysiri** 模式的「標準」從「s」音開始削；Siri 如果聽前半句就夠了，會擋不住。「加強」從「Hey」的中途開始削（測試中約 9 成抓得到），「Hey」最開頭的 0.1 秒左右還是原樣。
- 開了之後，對方聲音要多繞一圈經過本程式；程式沒開就聽不到對方。
- **最保險的做法**仍然是：通話時把 HomePod / iPhone 的「嘿 Siri」關掉，或把它放遠一點。另外，iPhone 的 Siri 本來就會比對「是不是主人的聲音」，所以別人說「Hey Siri」不一定每次都叫得醒。
